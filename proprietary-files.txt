# MediaTek proprietary files, extracted from the stock system image.
#
# Only the video call libraries below are still needed.
#
# The list used to carry the MediaTek framework .jars, mediatek-res.apk, their
# two permission files and two more /system/lib64 libraries, on the theory
# that mtkfusionrild needed a framework counterpart. Nothing loads them on
# LineageOS. Checked on the phone: no process maps any of them, no permission
# file other than their own names the .jars, and the vendor daemons use their
# own copies of the libraries, in /vendor and in the VNDK 29 APEX. Two of them
# were doing harm besides: com.mediatek.wfo.legacy.xml declared a shared
# library that put a stock .jar ahead of ImsService's own classes, and
# privapp-permissions-mediatek.xml allowlisted privileged permissions for
# forty-seven packages, most of which do not exist here.
#
# The old list is in git: `git show b2167a8:proprietary-files.txt`.

# Video calls over LTE.
#
# ImsService reaches the video call service through libmtk_vt_wrapper.so,
# which the stock ROM kept in /system/lib64 with what it links against. The
# vendor image has copies of some, which a system app may not load.
# libhidltransport and libhwbinder are linked too; AOSP folded them into
# libhidlbase in Android 11 but still builds them, so they come from device.mk
# rather than from here, where they would be defined twice.
#
# DISABLE_DEPS: extract-utils would list each library's DT_NEEDED as
# shared_libs, and soong wants a module for every one. Some are MediaTek HIDL
# interfaces that exist only in the vendor image; the linker finds them at
# runtime.
system/lib64/libmtk_vt_wrapper.so;DISABLE_DEPS
system/lib64/libvcodec_cap.so;DISABLE_DEPS
system/lib64/libvcodec_capenc.so;DISABLE_DEPS
system/lib64/vendor.mediatek.hardware.videotelephony@1.0.so;DISABLE_DEPS

# FM radio.
#
# libfmjni is NOT extracted, and that is deliberate.
#
# Up to LineageOS 21 it was: the stock library registers its native methods for
# exactly com/android/fmradio/FmNative, so the MediaTek fork and the LineageOS
# app fitted together without adaptation.
#
# LineageOS 22 builds the library itself. packages/apps/FMRadio commit 168f373
# ("jni: Move customisation to properties") took the config values MediaTek had
# hardcoded into its fork and moved them to ro.fm.* properties, which made the
# library device independent; commit f3eb07a dropped the soong_namespace that
# used to keep the source module out of the way. Shipping the blob now collides
# with the source module, and the build stops with
#
#   TARGET module FMRadio requires non-existent TARGET module: prebuilt_libfmjni:64
#
# because prefer:true renames the prebuilt to prebuilt_libfmjni while soong
# still exports it as libfmjni.
#
# The config values that were inside the blob are in device.mk, read out of it
# rather than guessed. See the comment there.

# THE VENDOR PARTITION IS NOT HERE, AND THAT IS DELIBERATE
#
# For a while the 1622 files of the stock vendor were listed below, one by one,
# so that the build could construct the image. It does not any more: the stock
# image ships whole and untouched,
#
#   BOARD_PREBUILT_VENDORIMAGE := vendor/doogee/s88pro/vendor.img
#
# which is what the charter asks -- a maintainer must not require a *modified*
# prebuilt vendor image, and a non-A/B device may rely on an OEM one as long
# as it asserts its version at flash time, which releasetools.py does.
#
# Constructing it is not a choice we postponed, it is one that cannot be made
# in this tree, and the reason is measured: a vendor built against the blobs'
# VNDK 29 needs BOARD_VNDK_VERSION := 29, and soong refuses that with
#   error: bionic/libc/Android.bp: "libc" depends on undefined module
#          "vendor_snapshot"
# A vendor snapshot is generated only from a complete Android 10 tree with the
# sources of the vendor modules. Those sources do not exist -- it is the same
# wall this whole project was born against, the one that led to rebuilding the
# kernel from the factory binary.
#
# What the blobs would have cost, measured and written down in case the
# question ever comes back: 85 files overlap between the blobs and what the
# build installs, which is 42 decisions and not 85, and 1537 of the 1622 need
# no decision at all. The old list survives in git -- `git show
# 9ef0088:proprietary-files.txt` -- with its 84 exclusions already made.
#
# The system files that used to stay here are gone as well: see the top of
# this file.
# ---------------------------------------------------------------------------
